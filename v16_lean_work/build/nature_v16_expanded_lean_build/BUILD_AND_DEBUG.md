# Build and debugging protocol

## 1. Preserve the original candidate

Before editing:

```bash
sha256sum $(find . -type f -not -path './.lake/*' | sort) > candidate-input.sha256
git init
git add .
git commit -m 'Unmodified expanded FMI-CNS Lean candidate'
```

## 2. Resolve dependencies

```bash
lake update
cat lake-manifest.json
lake build 2>&1 | tee build-attempt-01.log
```

The project intentionally uses the stable matched Lean/Mathlib `v4.32.0` tags. A version change is permitted only when the failure is genuinely toolchain-related; preserve the old failure log and document the change.

## 3. Debug in dependency order

Recommended order:

1. `Core/Types.lean`
2. `Core/Semantics.lean`
3. `Reflective/Subspace.lean`
4. `Projection/Conflation.lean`
5. `FMI/Operations.lean`
6. `FMI/Topology.lean`
7. `Order/Composition.lean`
8. `Order/Span.lean`
9. `Fragmentation/Backlog.lean`
10. `Fragmentation/Regional.lean`
11. `Fragmentation/SemanticLoss.lean`
12. `CNS/Lift.lean`
13. `CNS/NearSingular.lean`
14. `CNS/Dynamic.lean`
15. governance and propagation
16. Great Filter modules
17. CST modules
18. top-level theorems
19. tests
20. `AxiomReport.lean`

After each repair:

```bash
lake env lean path/to/file.lean
```

## 4. Theorem-strength rule

Do not change the mathematical meaning merely to obtain compilation. Classify each change as:

- syntax/API repair;
- proof repair with unchanged statement;
- stronger exposed premise;
- restricted domain;
- theorem refuted and replaced by countermodel;
- manuscript claim narrowed.

Record every nontrivial change in `debug-change-log.md`.

## 5. Mutation audit

At minimum confirm:

- a noninjective class relabelling does not preserve cognitive order;
- a genuine `Equiv` does preserve it;
- duplicate insertion does not increment order;
- Register and Recall cannot be generated by the L/G algebra;
- removal of the projection-separating witness blocks `cnsLift`;
- removal of the residual contract blocks the reversal field;
- a metric-changing map cannot inhabit `AdmissibleIso` without a metric proof;
- a nontrivial transport loop defeats `TrivialHolonomy`;
- missing external bridge implications prevent the conditional Great Filter theorem.

## 6. Axiom audit

Run:

```bash
lake env lean AxiomReport.lean > axiom-report.txt 2>&1
```

Inspect every theorem. Standard Mathlib classical or quotient axioms may appear and must be reported. No empirical premise may appear as a global axiom.

## 7. Clean independent build

Use a fresh container or clone. Preserve:

- OS and architecture;
- Lean version;
- Mathlib revision;
- `lake-manifest.json`;
- build stdout/stderr;
- axiom report;
- source hashes.

Only then update the manuscript to say that the corresponding theorem family is kernel-checked.
