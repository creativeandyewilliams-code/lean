SCOPE
-----
This certificate concerns slot L1 of the audit contract: the DECISION
SEMANTICS of the verdict algebra (the verdict lattice `Verdict`; the
composition rule `combine`; the fold `foldVerdicts`; the tree evaluator
`evalTree`/`evalForest`). It attests that these are internally consistent —
`combine` is a monoid with an absorbing element, the coherent and incoherent
fold conditions are exactly characterised, and the tree evaluator computes the
algebra's fold.

It does NOT certify the paper's substantive results (the global material-law
completion / observability blind spot), and it does NOT decide any per-node
coherence judgment. Leaf verdicts are INPUTS to `evalTree` (slot B1), exactly
as they are oracle inputs to the Python reference implementation. See
PACKAGE_README.md ("What this package is not").

6. NOTE — Python/Lean representational scope (disclosed)
--------------------------------------------------------
The two artifacts verify overlapping but not identical objects:

  * In the PYTHON reference, UNDETERMINED arises ONLY from budget exhaustion;
    budget accounting is exercised by the conformance tests (tests/), not by
    Lean.
  * In LEAN, `undetermined` is a leaf value supplied as INPUT and budget is not
    modelled at all; `node []` (an internal node with no children) folds to the
    empty-fold value `coherent`, a case the Python `Hypothesis` does not
    represent (a childless node there is a leaf awaiting an oracle verdict).

The Python <-> Lean agreement check in Section 1 is therefore run under ample
budget and restricted to trees both artifacts represent. The Lean development
certifies the verdict MONOID and the fold characterisations; the BUDGET
DYNAMICS that generate UNDETERMINED in the reference implementation are verified
on the Python side only. Slot L1 in the manuscript should state this.
